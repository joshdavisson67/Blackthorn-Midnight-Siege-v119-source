## Gameplay quality and implementation judgment

- **Implement the intent, not just the literal request.** Treat user instructions as descriptions of intended outcomes. Make reasonable, context-aware design decisions to produce complete, functional results without requiring the user to specify every obvious detail.
- **Validate gameplay usability.** When adding or modifying environments, check player dimensions, camera clearance, walkable surfaces, collision geometry, stair accessibility, enemy navigation, and interaction reach wherever applicable. A feature is not complete merely because its geometry or code exists.
- **Maintain believable proportions.** Environmental additions must use appropriate scale relative to the player and existing architecture. For example, new floors must provide adequate headroom and usable navigation space.
- **Preserve existing gameplay systems.** Consider how each change affects combat, AI, progression, economy, interactable objects, multiplayer-adjacent systems such as shared leaderboards, and performance. Avoid unintended changes to unrelated mechanics.
- **Respect the performance budget.** Prefer efficient geometry, reusable materials, optimized effects, and lightweight implementations. Avoid unnecessary draw calls, expensive shader operations, or excessive per-frame calculations.
- **Maintain visual and mechanical consistency.** New features should match the established atmosphere, architectural style, weapon behavior, feedback systems, and overall design language of Blackthorn.
- **Perform a self-review before completion.** Check whether the implementation fulfills the user's actual gameplay intent, not merely the wording of the instruction. Look for obvious usability problems, broken interactions, regressions, and missing edge cases. Fix issues discovered during review.
- **Distinguish verified results from assumptions.** Do not claim visual quality, frame-rate performance, or gameplay feel has been verified unless those aspects were actually tested. When browser rendering or interactive testing is unavailable, clearly identify the limitation.
- **Be proactive but stay within scope.** Correct obvious issues directly related to the requested change. Avoid unrelated redesigns, speculative features, or major architectural changes without explicit authorization.
